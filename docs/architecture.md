# pstack-pi 移植契约

## 目标与边界

把 pstack 的工程工作流移植为可安装的 Pi skills 包，而不是再实现一个 agent runtime。保留理解、设计、实现、独立审查、真实验证、交付和恢复能力；允许用户用已有 skill 替换具体实现。

原始工作流来源：`cursor/plugins` 的 `pstack/`，快照 `e31650eea443aaea1e84cc15d88c13f40080b275`。移植经验及可靠性修复参考：`michael-denyer/pstack-claude`，快照 `430a4f5d1fdcba0750ffa21e441ced5114f7d8ce`。保留上游 MIT 许可与署名，明确哪些是改写、替代和暂不支持，不宣称逐字或全平台等价。

## 已确认的执行选择

用户选择 A：**Herdr 优先，fresh subagent 可选，不静默切换后端。**

- 长期 owner、并行实现、swarm、arena 和正式独立审查优先使用 Herdr 承载的独立 Pi 会话。
- Herdr 负责终端、进程和会话定位及控制；pi-intercom 负责会话间通信；Git worktree 隔离并行写入。
- 短小、边界明确的调查可以使用 fresh-context subagent。可用性不等于派发授权。
- 不自建调度器、消息总线、任务数据库，也不要求安装者必须使用 pi-subagents。
- 没有合适后端时，明确说明限制。能够由主会话完成的普通工作可直接做；请求了独立审查或并行实验时，不得把主会话自评伪装为等价结果。
- 已启动的任务由原后端负责收尾。改变执行方式需明确决定，防止留下双写任务。

## 独立性与验收

- 新任务提供自包含 brief，不复制主会话历史；正式 reviewer 使用新上下文，不提前看实现者自评或其他 reviewer 结论。
- 每个写入者有独占 worktree。只读者可共用稳定代码快照。必须记录实际路径和版本，不能把 pane 分离误认为文件隔离。
- 模型由操作者或当前环境选择，不把此次使用的 provider/model ID 写成包默认值。
- 固定任务、会话、工作目录和代码版本，回报实际产物、验证命令及输出、未解决问题。
- Herdr idle/done、intercom 送达和 agent 自报成功都不等于验收通过。
- 主会话拥有需求、架构、结果采纳和集成权限；发布、合并、外部消息和破坏性操作仍服从用户授权。

## 包与 skill 结构

先交付标准 Pi package，`package.json` 显式列出 skills。使用 `pstack` 作为入口，其余入口使用 `pstack-` 前缀，避免占用已有 `how`、`why` 等短名称。原生调用使用 `/skill:<name>`，不为每个 skill 再生成一份命令包装。

覆盖上游适用于 Pi 的公共工作流及全部 23 个 playbook。Cursor 专属 Grok Bot UI、Benny 自动化和 UI 元数据不机械移植，须在覆盖表中说明。Claude 额外引入的 cursor-team-kit 命令不是本次原版能力兼容的必要前提；所需清理、PR 和验证行为仍要有可用路径。

23 条原则作为按需读取的内部 reference，不注册成 23 个公共 skill。每个实际引用的本地文件必须随包安装。

## 可替换能力

替换优先级：当前明确请求 → 项目 AGENTS.md 中的明确能力映射 → 包内默认工作流。

映射使用简单 Markdown 表，不新增解析器、注册表或配置 extension。只引用本次环境真实发现并读取的 skill。替换只改变实现，不能删除原任务的必要产物、证据或独立性要求。目标不存在或能力不匹配时说明原因，使用可用默认路径或请求选择，不虚构调用成功。

例如 Ponytail 可以替代代码简化指导，但不是自动替代运行时验证；domain-modeling 可以承担术语和领域建模，但不自动等价于多方案设计；Herdr 是执行方式，不是 swarm 的任务拆分与汇总规则。

## 适度流程与真实验证

简单改动直接实现并做最小真实检查，不强制多模型、架构竞赛、PR 或任务清单。需要独立判断、存在实质设计分歧或长期并行时再使用对应流程。只读问题不得被路由到写代码或开 PR。

项目验证 skill 应记录 Launch、Doctor、Drive、Evidence、Cleanup 和功能地图，并至少亲自跑通一个功能后才称为可用。无可用 UI 驱动时明确 blocked，不能以编译或截图文件存在代替真实行为证据。

暂停/恢复优先使用 Pi 会话及原执行后端已有记录。长期项目的工作单元、证据账本和交接可用可读文件，不能因此引入第二套通用 orchestration store。PR 工作可使用已授权的 gh 和项目 CI；外部集成未验证要如实标注。

## 验收

- 每个原版公共 skill 和 playbook 在覆盖表中有明确去向与差异。
- 无失效的 Cursor/Claude 工具、路径、硬编码模型或未捆绑文件调用。
- 使用 Pi 的真实资源加载器验证 manifest、skill 发现、命名和诊断；测试不调用模型或读取用户私有会话。
- 用 Node 内置测试覆盖本地引用、覆盖表、打包边界和关键运行时契约；不新增测试框架。
- 包可通过本地路径安装；说明哪些验证是静态检查、资源发现或真实工作流 smoke，禁止夸大。
- 独立审查后由主会话检查产物与证据，才宣布交付。
